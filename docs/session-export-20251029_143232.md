## Current State

```
Website Search Filter (year/price/mileage)
    ↓
Scraper parses listing
    ↓
should_exclude_vehicle() - checks exclusion list only
    ↓

    ↓

```

2. Price against vehicle-type specific `max_price` (€35k)
3. Mileage against `config['search']['max_mileage_km']` (100k km)
4. Required features aren't enforced (just tracked)

### Option 2: Add Soft Validation (monitoring only)
- Log warnings for cars outside criteria (don't block)
- Add `confidence_score` field to database (0-100%)
- Show confidence indicators in dashboard
- Effort: 2-3 hours

**Implementation:**
```python
def _calculate_confidence_score(self, car_data, config):
    score = 0
    checks = 0
    
    # Year check (25 points)
    if car_data['year'] >= config['search']['min_year']:
        score += 25
    checks += 1
    
    # Price check (25 points)
    vehicle_type = config['vehicle_types'][car_data['make_model']]
    if car_data['price'] <= vehicle_type['max_price']:
        score += 25
    checks += 1
    
    # Mileage check (25 points)
    if car_data['mileage_km'] <= config['search']['max_mileage_km']:
        score += 25
    checks += 1
    
    # Features check (25 points)
    if car_data['has_all_required_features']:
        score += 25
    checks += 1
    
    return score
```

**Pros:**
- Visibility into data quality
- Doesn't block any cars
- Can filter by confidence in dashboard
- Helps identify pattern issues

**Cons:**
- Requires database schema change
- Dashboard updates needed
- Still saves non-compliant cars

### Option 3: Add Strict Validation (with exceptions)
- Block cars that don't meet criteria
- Requires exception rules in config (e.g., `acceptable_year: 2020 for Enyaq`)
- Guarantees data quality but loses flexibility
- Risk of missing good deals
- Effort: 4-5 hours

**Implementation:**
```python
def _validate_car_requirements(self, car_data, config):
    """Validate car meets all requirements before saving."""
    errors = []
    
    # Check year (with exceptions)
    min_year = config['search']['min_year']
    exceptions = config.get('exceptions', {}).get('year', {})
    
    if car_data['year'] < min_year:
        model_key = f"{car_data['make']} {car_data['model']}"
        if model_key not in exceptions or car_data['year'] < exceptions[model_key]:
            errors.append(f"Year {car_data['year']} < minimum {min_year}")
    
    # Check price
    vehicle_type = config['vehicle_types'].get(car_data['make_model'])
    if vehicle_type and car_data['price'] > vehicle_type['max_price']:
        errors.append(f"Price €{car_data['price']:,} > max €{vehicle_type['max_price']:,}")
    
    # Check mileage
    if car_data['mileage_km'] > config['search']['max_mileage_km']:
        errors.append(f"Mileage {car_data['mileage_km']:,}km > max {config['search']['max_mileage_km']:,}km")
    
    # Check required features
    if not car_data['has_all_required_features']:
        errors.append("Missing required features")
    
    return errors
```

**Config additions needed:**
```yaml
exceptions:
  year:
    "Škoda Enyaq": 2020  # Allow 2020 for Enyaq
    "Volkswagen ID.4": 2020
```

**Pros:**
- 100% confidence in saved cars
- Clean, compliant dataset
- Clear exception rules
- Prevents database pollution

**Cons:**
- Requires exception management
- May miss unexpected good deals
- More complex configuration
- Risk of being too restrictive
